# Release Notes — v0.6.0

**Milestone:** M5 — Review workflow, revisions and supersession
**Date:** 2026-08-01
**Schema version:** 1 (unchanged)
**Status:** The knowledge can now be worked, and its history read back.

---

## Executive summary

Two things happen in this release.

**The backlog became workable.** Two independent queues — 26 items held back
from minting, 45 objects no rule could classify — are now one workflow with one
listing, one ordering and bulk actions. The demonstration cleared 45 items in a
single command.

**The Time Machine got a reader.** The engine has been writing revision
snapshots since M2 and reading them never. `ke history` now reconstructs an
object's past from what the object itself carries — no Git archaeology, no
network, no AI.

Reading them back immediately found damage that four milestones of green
pipelines had not. That is the point.

| | v0.5.0 (M4) | v0.6.0 (M5) |
|---|---|---|
| Review backlogs | 2, separate | **1 workflow, 3 kinds** |
| Bulk triage | none | **`--all --kind`** |
| History readable | no | **`ke history [--at N]`** |
| History validated | no | **5 chain checks + flip-flop detection** |
| Lifecycle stages | 6 (one unused) | **5** |
| Tests | 340 | **366** |

## What you can now do

```bash
ke review list                          # every pending decision, one view
ke review next                          # the single most urgent
ke review show <key>                    # full context
ke review resolve --all --kind unclassified   # bulk
ke history MSF-2026-07-001              # the object's whole past
ke history MSF-2026-07-001 --at 2       # one revision
ke supersede MSF-2025-11-004 --by MSF-2026-07-001
```

`indexes/review-queue.md` now shows every kind with counts, visible in the
GitHub UI without running anything.

## Validating produced knowledge, not just execution

The lesson from M2–M4 was applied directly, and it paid immediately.

Reading revision histories back turned up **35 objects carrying 11 revisions
each, every one recording the identical field change** — residue from the M3
flip-flop bug, produced before it was fixed.

**Why nothing caught it:** every individual revision was well-formed. The
corruption was visible only in the *pattern*, and no check looked at patterns.
`ke validate` had reported zero errors throughout.

`ke validate` now checks the chain itself — numbering, chronology, an object
agreeing with its own latest snapshot, revisions that record no change — and
flags three or more consecutive identical revisions as the flip-flop signature.

**The 35 existing objects are reported, not rewritten.** Their revisions
truthfully record what the engine did; rewriting history to look tidier would
make it less true, and the append-only rule exists for exactly this temptation.
That is a data-integrity decision, so it is raised for the maintainer rather
than taken here — see [`M5_ARCHITECTURE_REVIEW.md`](../reviews/M5_ARCHITECTURE_REVIEW.md) §5, F1.

## Major decisions

### Unify the workflow, not the storage ([ADR-0036](../adr/0036-unified-review-workflow.md))

Three backlogs growing in parallel is how a review queue becomes permanent: each
one is somebody else's problem and the total is never visible in one place.

But each kind keeps the storage that suits it. A queued item has no Feature ID
and nowhere else to live; a flagged object's `needs_review` belongs to the
object, because the repository is the source of truth. A `ReviewTask` is a
**view**, assembled on demand and never persisted — a stored view of state that
lives elsewhere is a second copy waiting to disagree.

**Adding a kind is one provider function plus one entry.** Listing, ordering,
filtering, bulk actions and `next` come free. That is what makes routing a future
review need here cheaper than building a fourth silo.

### Supersession is a status, not a lifecycle stage ([ADR-0035](../adr/0035-supersession-is-status-not-lifecycle.md))

ADR-0029 flagged `Lifecycle.SUPERSEDED` versus `status: replaced` as the softest
part of that design and left it for M5. Implementing supersession settled it in
one sentence:

> An object whose *feature* was replaced has still been fully **acquired**.

Its lifecycle stays `minted`; the replacement is recorded in `status`, which
already meant exactly that. The stage was referenced by no code and carried by no
stored object, and has been removed.

## Assumptions that were disproven

### 1. "Well-formed records mean healthy data"

Every one of those 350 junk revisions passed every schema check. Validity is not
correctness, and a check that only looks at one record at a time cannot see a
pattern.

### 2. "A data model that has been written for three milestones is probably right"

The Time Machine's snapshots had never been read. The first read found them
polluted. **A data model nobody reads is a data model nobody has validated.**

### 3. "Define the states now, use them later"

`Lifecycle.SUPERSEDED` and `ARCHIVED` were both defined in M3 without producers.
One turned out to be redundant and cost a glossary entry, an ADR paragraph and a
second ADR to remove. **Define a state when something produces it** — guessing at
semantics in advance costs more than adding the value later.

## Known limitations

- **35 objects carry polluted history**, reported as warnings and awaiting a
  maintainer decision (TD-16).
- **Revision review only surfaces retitles.** Date corrections and rewrites are
  recorded but not queued — a deliberate filter with no evidence behind the
  threshold yet (TD-15).
- **Bulk actions have no `--dry-run`.** Fine while every bulk action is
  reversible; not fine for the first one that is not (TD-14).
- **`collect()` reads every object per call** — it shares TD-2's fate.
- **`Lifecycle.ARCHIVED` is written for queued items but not stored objects.**
  The asymmetry is unexplained.
- Full list in [`M5_ARCHITECTURE_REVIEW.md`](../reviews/M5_ARCHITECTURE_REVIEW.md) §6.

## Breaking changes

`Lifecycle.SUPERSEDED` removed. Safe because nothing referenced it and no stored
object carried it — the same removal after M6 would have needed a migration.
`SCHEMA_VERSION` stays **1**.
