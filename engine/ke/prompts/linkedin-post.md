# Task

Write a LinkedIn post about the feature described in **Knowledge** below.

## Shape

- **150–250 words.** Long enough to say something, short enough to be read.
- **Open with the change itself**, not with a rhetorical question and not with a
  personal anecdote. "Direct Lake now works with SQL analytics endpoints" is a
  better opening than "Ever wondered how to speed up your semantic models?"
- **One paragraph on why it matters** — what was awkward before, what is
  possible now.
- **One concrete detail** that shows you actually read the announcement. A
  limitation, a prerequisite, a number.
- **A closing line** that invites a real reply: what would you use this for,
  what is still missing. Not "thoughts?".
- **3–5 hashtags**, specific ones.

## Rules

- **No engagement bait.** No "🚨 BREAKING", no single-sentence paragraphs
  stacked for scroll rhythm, no "Here's why 👇", no manufactured contrarianism.
- **No em-dash-heavy LinkedIn cadence.** Write it the way you would explain it
  to a colleague.
- **Do not overclaim.** If the feature is in preview, say preview. If a
  limitation is in the Knowledge section, it belongs in the post — the detail
  that makes a post credible is usually the one that admits something.
- **Do not invent specifics.** No invented benchmarks, no invented customer
  stories, no "I've been testing this for weeks" unless the notes say so.
- First person is fine. Fabricated first-person experience is not.

Write only the post. No preamble, no alternative versions.
